# Affiliate Content Writer — Monetized Pattern Replicator

Write SEO content optimized for affiliate revenue following Koray's micro-semantic methodology. Extends the standard `/content-writer` with comparison tables, product cards, pros/cons, and affiliate CTAs.

## Arguments

- `brief` (optional): Path to a semantic brief file (generated by `/semantic-brief`)
- `keyword` (optional): If no brief provided, the target keyword to write for
- `product-type` (optional): Product category for commission context (electronics, fitness, home, etc.)
- `output` (optional): File path to save the content

## Instructions

**You are a pattern replicator, NOT a creative writer.** All rules from `/content-writer` apply. This skill adds affiliate monetization elements on top.

### Core Content Rules (from /content-writer — MUST follow):

1. Start every answer with the answer
2. Use imperative verb structures
3. Use specification structures ("X ranges from £Y to £Z")
4. No commas except in enumerations/ranges
5. No LLM fluff words (zero tolerance)
6. One macro context per page
7. H2 headings as user questions
8. 40-word extractive answers under each H2
9. Use SERP verbs and nouns exactly
10. Follow prescribed order from the brief

### Additional Affiliate Content Rules:

11. **Price anchoring**: Always include price ranges ("costs £X-£Y" or "ranges from £X to £Y")
12. **Specification tables**: Every product mention includes key specs in a comparison table
13. **Winner declaration**: State the best pick clearly — "Buy X for Y because Z"
14. **No fake urgency**: No "limited time", "hurry", "don't miss out"
15. **Honest assessment**: Include genuine limitations — this builds trust AND ranks better

### Process:

**Step 1: Load Brief or Research**
- If brief file provided, read it
- If keyword provided, WebSearch the keyword + "best", "review", "vs"
- Extract: central entity, products to compare, key attributes, price ranges, SERP patterns

**Step 2: Product Research**
- WebSearch for current product information, prices, specifications
- Identify 5-8 products for roundup content (or 2-3 for comparison content)
- For each product gather: name, price range, key specs, pros, cons, best-for use case

**Step 3: Write Article Structure**

For **Roundup Articles** ("Best X 2026"):

```markdown
# Best {Product Category} {Year}

{Introduction: 150-200 words following content-writer rules}
{Mention total products tested/reviewed, time spent reviewing}

## Quick Comparison Table

| Product | Best For | Price | Key Spec | Rating |
|---------|----------|-------|----------|--------|
| {Winner} | Overall | £X | spec | 9.5/10 |
| {Runner-up} | Budget | £X | spec | 9/10 |
| ... | ... | ... | ... | ... |

## {Product 1 Name} — Best {Use Case}

{40-word representative answer}

### Key Specifications
| Spec | Value |
|------|-------|
| ... | ... |

### What We Like
- {Pro 1 — specification structure}
- {Pro 2}
- {Pro 3}

### Limitations
- {Con 1 — honest, specific}
- {Con 2}

### Verdict
{2-3 sentences. "Buy {product} for {use case} because {reason}."}

**Price**: £X — [Check current price on Amazon →](AFFILIATE_LINK_PLACEHOLDER)

## {Product 2 Name} — Best {Use Case}
{Same structure as above}

...

## How to Choose {Product Category}

### {Buying Factor 1}?
{40-word answer with specification structures}

### {Buying Factor 2}?
{40-word answer}

## Final Verdict

{Summary table + clear winner declaration}
```

For **Comparison Articles** ("X vs Y"):

```markdown
# {Product A} vs {Product B}: Which {Category} {Year}

{Introduction}

## Quick Comparison

| Feature | {Product A} | {Product B} |
|---------|-------------|-------------|
| Price | £X | £Y |
| {Key spec} | value | value |
| Best For | {use case} | {use case} |
| Our Pick | {Yes/No} | {Yes/No} |

## {Feature 1} Comparison
{Direct comparison with specification structures}

## {Feature 2} Comparison
{Direct comparison}

## Who Should Buy {Product A}?
{Imperative structure: "Choose {A} for {use case}"}

## Who Should Buy {Product B}?
{Imperative structure: "Choose {B} for {use case}"}

## Our Verdict
{Clear winner with reasoning}
```

**Step 4: Affiliate Link Placeholders**
- Insert `AFFILIATE_LINK_PLACEHOLDER` where affiliate links will go
- Format: `[Check price on Amazon →](AFFILIATE_LINK_PLACEHOLDER_{PRODUCT_SLUG})`
- Add a note at the end: "Affiliate links will be replaced with tracking URLs before publishing"

**Step 5: Schema Markup Suggestions**
Generate recommended schema for the article:
- Product schema for each reviewed product
- Review/Rating schema
- ItemList schema for roundup articles
- FAQPage schema for the buying guide section

**Step 6: Self-Audit**
Run all `/content-writer` compliance checks PLUS:
- [ ] Every product has a price range mentioned
- [ ] Comparison table is present and complete
- [ ] At least 1 genuine limitation per product
- [ ] Clear winner/verdict declared
- [ ] Affiliate link placeholders present
- [ ] Schema recommendations included
- [ ] No fake urgency or hype language

**Step 7: Output**
Deliver:
1. Full article in markdown
2. Word count report (total + per section)
3. Self-audit compliance summary
4. Schema markup recommendations
5. List of affiliate link placeholders to replace

Save to the specified output path.

### Tone Guidelines:

- **Authority**: Write as someone who has tested/used the products
- **Directness**: State opinions clearly — "This is the best X because Y"
- **Specificity**: Use exact numbers, specs, measurements — never vague claims
- **Honesty**: Every product has downsides — mention them
- **Helpfulness**: Match products to use cases — "Buy X if you need Y"
